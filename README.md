# Breast Cancer Classification

A production-grade malignant/benign classifier for FNA (Fine Needle Aspirate)
breast mass measurements — built as a decision-support tool with a validated
data pipeline, tracked experiments, a tuned model, SHAP explainability, a
served API, a full test suite with a model-quality gate, CI/CD, and
monitoring, not just a notebook.

## Business Problem

Radiologists currently review FNA cell measurements manually to flag
malignant vs. benign breast masses. In a screening context, the two ways a
model can be wrong are not equally costly: a missed cancer case (false
negative) is far more dangerous than an unnecessary follow-up test (false
positive). Most tutorial ML projects optimize for accuracy, which is
actively misleading here — on this dataset, a model that always predicts
"benign" scores ~63% accuracy while catching zero cancer cases. This project
is built around that asymmetry from the ground up: every model-selection
decision optimizes for **recall on the malignant class**, not accuracy.

## Solution Overview

An end-to-end pipeline: data is validated against a strict schema before
training, three model families (logistic regression, random forest,
XGBoost) are compared via cross-validation, the winner is tuned with Optuna,
every prediction is explained with SHAP, the model is served through a
FastAPI endpoint with automated tests gating deployment, and a Streamlit
dashboard exposes results to non-technical stakeholders.

## Key Results

- **Recall (malignant): 95.2%** — 40 of 42 malignant test cases correctly caught
- **False negatives: 2 of 42** — the metric that matters most in a screening context, minimized directly (not a side effect of optimizing accuracy)
- **ROC-AUC: 99.6%** — near-complete separation between classes across every decision threshold
- **Precision (malignant): 97.6%** — few unnecessary follow-up tests triggered

## Quick Start

```bash
git clone https://github.com/<your-username>/<your-repo>
cd breast-cancer-classification

python -m venv .venv
source .venv/bin/activate      # Windows: .venv\Scripts\activate
pip install -r requirements-dev.txt

# Train, then tune (tuning needs a trained model to know which type won)
python -m src.models.train
python -m src.models.tune

# Run the test suite (includes the model-quality gate)
pytest tests/ -v

# Serve the API
uvicorn api.main:app --reload
# -> http://localhost:8000/docs

# Or run the dashboard
streamlit run app/streamlit_app.py
```

**Or with Docker** (trains + tunes automatically inside the build):

```bash
docker compose up --build
```

## Technical Details

**Data:** Wisconsin Diagnostic Breast Cancer (WDBC) dataset, 569 samples, 30
features, loaded through a pandera schema that validates every row (no
nulls, no negative measurements, no unexpected columns) before training —
the raw source is treated as untrusted, even though it's a well-known public
dataset.

**Model:** Logistic Regression, chosen over Random Forest and XGBoost after
5-fold stratified cross-validation comparison (recall was the selection
metric). Tuned via Optuna (40-trial Bayesian search) to `C≈3.07`, `L2`
penalty, `saga` solver. Imbalance handling: class-weighting (configurable
alternative: SMOTE, applied only to the training fold to avoid leakage).

**Evaluation:** 80/20 stratified train/test split, 5-fold cross-validation
during model selection, held-out test set for final reported metrics. A
model-quality gate test in the CI pipeline fails the build if recall or
ROC-AUC regress below the threshold set in `configs/config.yaml` — this is a
test about the model itself, not just the code.
